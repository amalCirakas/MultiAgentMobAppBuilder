# Terminal app builder: capability expectations (`MODULE=builder`)

This document summarizes what **`build_app.py`** + **`MODULE=builder`** reliably produce today versus what an “end‑to‑end product” might imply.

## What “fullstack” means here

Choosing **React Native `fullstack`** and **`--backend-runtime node`** scaffolds:

- **`Project/<slug>/`** — RN app generated by **`react-native init`**  
- **`Project/<slug>/server/`** — Express app with **`GET /health`** and a deterministic **`/api/v1/notes`** CRUD surface (JSON, in‑memory MVP), **`express.json`**, CORS for dev, default port **3090**

CrewAI agents are instructed to wire **`src/db/appService.ts`** to **`${getApiBase()}/api/v1/notes`** via **`fetch`** when that stack/runtime combination is detected, using **`src/config/api.ts`** (written by **`build_app.py`** before codegen).

## What “fullstack” does **not** guarantee by itself

- **Production-grade auth**, databases, migrations, Prisma/SQLite, or multi-tenant APIs — unless you extend the scaffold or prompts  
- **Multi-screen navigation and design-system polish** — the pipeline emits one primary screen (**`AppScreen.tsx`**) per run; richer UX requires extra prompts, stages, or manual work  
- **Automatic correctness of Metro / native builds** — red screens and bundler errors still require reading the Metro log (see **`README`** troubleshooting)

Treat the Node server as an **iterable scaffold**, not your final backend unless you deliberately harden it.

## Minimal manual steps to exercise HTTP on device

See **`README`** “Full-stack Notes dev plumbing” — **`adb reverse`** for physical USB devices, Emulator URL **`10.0.2.2:3090`**, and **`cd server && npm install && npm start`**.
